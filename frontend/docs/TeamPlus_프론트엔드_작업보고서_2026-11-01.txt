======================================================================
1. 현재 작업 결과 및 현재 완성 범위
======================================================================

광운대학교 학생의 모임 일정 조율과 장소 탐색을 위한 Android 프론트엔드
MVP를 구현했다. 정적인 화면만 있는 상태가 아니라, 모임 생성·팀원 관리·
시간표 입력·공강 계산·장소 조회·가상 예약·취소가 로컬 데이터로 동작한다.

현재 완성 범위는 ""백엔드 없이 독립 실행되는 로컬 시연용 프론트엔드""이다.
(실제 계정, 서버 데이터 공유, AI 추천 및 실제 학교 시설 예약은 연결하지
않았다). 가상 예약 완료를 실제 시설 예약 완료로 해석하면 안 된다.

핵심 화면 9개를 구현했고 Android 에뮬레이터에서 앱을 실행했다.
사용자가 앱을 직접 테스트한 뒤 정상 동작을 확인했다.
본 보고서 작성 시점에는 소스 기준 타입·로직·의존성 검사를 재확인했다.

3. 화면별 구현 내용
======================================================================

3-1. 홈 — app/(tabs)/index.tsx
- 모임 목록, 모임별 팀원 이름·인원, 새 모임 생성 버튼 제공.
- 최근 수정한 모임의 전원 공강 블록 수를 표시하고 공강 화면으로 연결.
- 새 모임은 이름 "새로운 모임", 기본 팀원 건우·승균·휘서로 생성.
- 생성 즉시 저장하며, 편집 화면에서 뒤로 가도 생성한 모임은 유지됨.
- 모임이 없을 때 안내 화면 제공.

3-2. 모임 및 팀원 관리 — app/group/[id].tsx
- 모임 이름·팀원 이름 자동 저장, 팀원 추가·삭제 구현.
- 마지막 팀원 1명은 삭제할 수 없도록 제한.
- 팀원 삭제 전 확인하며 해당 팀원의 시간표도 함께 제거.
- 모임 삭제 전 확인하며 해당 모임의 가상 예약은 취소 상태로 변경.
- 팀원별 시간표 및 공통 공강 화면으로 이동 가능.
- 현재는 한 기기에서 모임 생성자가 모든 팀원 정보를 직접 입력하는 방식.

3-3. 팀원별 시간표 — app/timetable/[id].tsx
- 월~금, 1~6교시의 30개 블록을 표시.
- 09:00~18:00를 90분씩 구분하며 학기 중 매주 반복되는 시간표로 처리.
- 팀원 칩으로 입력 대상을 선택하고 셀 터치로 수업/공강 상태 전환.
- 선택한 팀원의 busy 배열만 변경하여 다른 팀원의 입력을 유지.
- 변경 직후 저장하고 공통 공강 계산에 반영.

3-4. 공통 공강 — app/availability/[id].tsx
- 각 시간대의 참석 가능 인원/전체 인원을 숫자와 색으로 표시.
- 전원 참석 가능한 블록 수와 선택 시간대의 참석·불참 팀원 명단 제공.
- 참석 가능 인원 내림차순으로 정렬하고, 동률은 요일·교시순으로 표시.
- 상위 5개 또는 전체 30개 결과 표시를 전환 가능.
- 공강 선택은 상세 확인 기능이며 예약 화면으로 자동 이동하지 않음.

3-5. 장소 목록 — app/(tabs)/places.tsx
- 시연용 장소 3곳: 집현전, 중앙도서관 라운지, 캠퍼스 커피룸.
- 장소 이름·태그 검색, 전체/교내/카페 필터 구현.
- 이름, 위치, 수용 인원, 특징, 가상 예약 가능 여부 표시.
- 로딩·조회 실패 시 재시도·검색 결과 없음 상태를 구분.
- 장소 데이터는 예시이며 실시간 시설 정보나 실제 업소 검색이 아님.

3-6. 장소 상세 — app/place/[id].tsx
- 설명, 위치, 인원, 특징 및 시연 데이터 안내 표시.
- 현재 데이터에서는 집현전만 가상 예약 화면으로 연결.
- 다른 장소는 목록으로 돌아가는 동작 제공.

3-7. 집현전 가상 예약 — app/booking.tsx
- 모임 → 인실·호실 → 날짜 → 시간 → 확인 → 완료 흐름 구현.
- 시연용 호실: 201호·202호(4인실), 301호(6인실), 302호(8인실).
- 오늘부터 30일 범위, 시작 시각 09~18시의 1시간 슬롯 제공.
  마지막 슬롯은 18:00~19:00이며 수업의 90분 교시와 별개로 처리.
- 예약됨·내 예약·지난 시간·같은 모임의 동시간 예약 상태를 표시.
- 인원 초과, 존재하지 않는 방·모임, 잘못된 날짜·시간, 중복 예약 차단.
- 예약 확인 모달, 성공 화면, 오류 안내 및 예약 내역 이동 구현.
- 고정 시드 점유와 사용자 로컬 예약을 합쳐 예약 가능 여부를 계산.

3-8. 내 가상 예약 — app/(tabs)/reservations.tsx
- 활성 예약과 취소 내역을 구분하여 표시.
- 날짜, 시간, 호실, 모임명, 예약 번호 표시.
- 취소 확인 후 상태를 cancelled로 변경하고 취소 기록은 보존.
- 사용자 예약 취소 시 그 슬롯을 다시 예약할 수 있음.
  단, 시드로 예약된 슬롯은 사용자 취소로 해제되지 않음.

3-9. 설정 — app/(tabs)/settings.tsx
- 라이트·다크·기기 설정에 따름 선택 및 저장.
- 최초 기본값은 라이트이며, 기기 설정 선택 시 시스템 색상 모드 반영.
- 앱의 시연 범위, 로컬 저장 방식, 외부 라이선스 안내 포함.
- 아이보리·화이트·버건디 디자인, 다크 토큰 및 공통 타이포그래피 적용.

4. 주요 함수·컴포넌트와 코드 설명

4-1. 데이터 모델 — src/domain/model.ts

Group / Member / Reservation / AppData
  모임·팀원·예약·전체 저장 상태의 TypeScript 구조를 정의한다.
  Member.busy는 수업이 있는 블록의 키 배열이다.
  예: '0-0'은 월요일 1교시, '1-2'는 화요일 3교시를 의미한다.
  ownerId, inviteCode, 선택적 userId 필드는 향후 연동을 위한 구조이며,
  실제 인증·소유권 검증·초대 기능은 구현되어 있지 않다.

uid()
  현재 시각과 난수를 조합해 모임·팀원·예약에 사용할 로컬 ID를 만든다.
  서버에서 발급하는 사용자 ID나 인증 토큰은 아니다.

localDate(date), dateAt(offset), hourLabel(hour)
  각각 기기 현지 날짜를 YYYY-MM-DD로 변환하고, 오늘 기준 날짜를 만들며,
  예약 시작 시각을 1시간 구간 문자열로 표시한다.

4-2. 모임 생성·수정 — 화면 내부 함수

Home의 create() — app/(tabs)/index.tsx
  새 Group과 기본 팀원 3명을 만들고 전역 groups 앞에 추가한 뒤
  해당 모임의 관리 화면으로 이동한다.

GroupScreen의 change(fn) — app/group/[id].tsx
  현재 모임에만 전달된 수정 함수를 적용한다.
  updatedAt을 갱신하고 update()를 호출해 상태와 저장을 함께 처리한다.
  팀원 추가·이름 변경·팀원 삭제에 공통으로 사용한다.

시간표 셀의 onPress — app/timetable/[id].tsx
  별도 toggle 함수 이름 없이 이벤트 내부에서 구현했다.
  선택 팀원의 busy에 key가 있으면 제거하고 없으면 추가한다.
  예: 월요일 1교시를 다시 누르면 수업에서 공강으로 바뀐다.

모임 삭제 Confirm의 onConfirm — app/group/[id].tsx
  선택 모임을 groups에서 제외하고 해당 모임의 예약은 cancelled로 바꾼다.
  별도 deleteGroup() 함수가 아니라 확인 콜백 안에 구현되어 있다.

4-3. 공강 계산 — src/domain/availability.ts

availability(group)
  입력: 팀원별 busy 배열이 포함된 Group.
  처리: 30개 시간대별로 busy에 key가 없는 팀원과 있는 팀원을 구분.
  반환: key, day, period, available, unavailable, count, total 배열.
  예: 팀원 3명 중 2명의 busy에 '0-0'이 있으면 해당 시간은 1/3명 가능.
  화면이나 저장소에 의존하지 않는 순수 계산 함수이다.

rankedAvailability(group)
  availability() 결과를 참석 가능 인원 내림차순으로 정렬한다.
  동률이면 월→금, 같은 요일이면 1→6교시순이다.
  공강 화면의 추천 순서와 홈의 전원 공강 블록 수 계산에 사용한다.
  AI 추천 알고리즘은 아니며, 참석 인원에 따른 규칙 기반 정렬이다.

4-4. 예약 규칙 — src/domain/booking.ts

isValidDate(value)
  YYYY-MM-DD 형식 및 실제 존재하는 날짜인지 검사한다.
  날짜를 다시 변환하여 2월 31일 같은 자동 보정 날짜를 거부한다.

isSeedOccupied(roomId, date, hour)
  호실·날짜 문자열의 해시와 시간을 사용해 시연용 점유 여부를 계산한다.
  동일한 입력에는 동일한 결과를 반환하므로 새로 열어도 점유가 일정하다.
  실제 학교 예약 현황을 조회하는 함수가 아니다.

isOccupied(reservations, input)
  시드 점유 또는 동일 호실·날짜·시간의 활성 로컬 예약이 있으면 true.
  화면의 선택 불가 표시와 최종 예약 검증에 사용한다.

book(data, input, now)
  입력: 현재 AppData, groupId·roomId·date·hour, 선택적 현재 시각.
  방·모임 존재, 시간 범위, 유효 날짜, 오늘 이후 30일 범위, 과거 시간,
  방 수용 인원, 방 중복, 같은 모임의 동시간 다른 방 중복을 검사한다.
  위반하면 Error를 던지고, 성공하면 새 Reservation을 포함한 AppData 반환.
  원본 data를 직접 변경하지 않으며 저장 자체는 AppProvider에 맡긴다.

cancel(data, id)
  지정 예약의 status를 cancelled로 바꾼 새 AppData를 반환한다.
  기록을 지우지 않기 때문에 취소 내역 화면에 계속 표시할 수 있다.

Booking의 submit(), resetSelection() — app/booking.tsx
  submit()은 update(d => book(...))로 최종 검증 후 예약을 반영한다.
  성공·실패에 따라 화면 상태와 오류 메시지를 변경한다.
  resetSelection()은 모임·방·날짜 변경 시 이전 시간 선택과 오류를 지운다.

4-5. 로컬 저장소 — src/data/repository.ts, src/data/seed.ts

initialData()
  저장값이 없을 때 사용할 기본 모임·시간표·라이트 테마를 만든다.
  최초 예시 모임은 '오픈소스 프로젝트'이며 신규 모임 생성과는 별개이다.
  새로 생성하는 모임의 기본 이름 3명은 model.ts의 상수로 관리한다.

validGroup(g), decodeData(raw)
  저장 문자열을 파싱하고 데이터 버전·테마·모임·시간표·예약 구조를 검사.
  손상된 데이터는 오류로 처리하여 기본값으로 조용히 덮어쓰지 않는다.
  서버 보안 검증을 대신하는 기능은 아니다.

StoragePort
  getItem()/setItem() 형태의 저장 인터페이스이다.
  실제 앱에는 AsyncStorage를, 자동 테스트에는 MemoryStorage를 주입한다.

LocalRepository.load()
  'kw-meet:v1' 키를 읽고 검증한다. 값이 없으면 initialData()를 반환한다.
  seedNamesVersion으로 기존 '새로운 모임' 3인 그룹의 기본 이름을 한 번
  갱신한다. 시간표·예약·테마와 갱신 완료 후의 사용자 이름 수정은 유지한다.

LocalRepository.save(data)
  AppData를 JSON 스냅샷으로 만든 뒤 Promise 큐 순서대로 기록한다.
  빠른 연속 수정으로 오래된 저장이 최신 저장을 덮는 상황을 방지한다.
  앞선 저장 실패 뒤에도 후속 저장이나 재시도를 수행할 수 있다.

LocalRepository.places()
  현재는 시연용 PLACES 배열을 Promise로 반환한다.
  장소 화면은 이 메서드를 통해 조회하며, 추후 API 조회로 교체할 경계이다.

4-6. 전역 상태 — src/state/AppProvider.tsx

AppProvider(), useApp()
  모임·예약·테마와 로딩·오류·저장 상태를 Context로 공유한다.
  화면은 useApp()을 통해 상태와 update() 등에 접근한다.

reload()
  저장소 데이터를 읽어 메모리 상태를 복원하고 로딩·오류를 갱신한다.
  최초 앱 시작 및 불러오기 재시도에 사용한다.

update(change)
  최신 데이터에 변경 함수를 적용한 후 화면 상태와 저장을 갱신한다.
  useRef의 최신 값을 즉시 바꿔 연속 예약이 오래된 상태를 쓰는 것을 줄인다.
  이 방식의 중복 방지는 단일 앱 내부에 한정되며 서버 동시성 제어는 아니다.

persist(next), retrySave()
  persist()는 저장 진행·성공·실패 상태를 관리한다.
  revision 번호로 이전 저장 응답이 최신 저장 표시를 덮지 않게 한다.
  retrySave()는 현재 메모리의 최신 스냅샷 저장을 다시 시도한다.
  저장 실패 시 안내가 표시되며, 저장 전 앱 종료 시에는 변경 유실 가능성이 있다.

4-7. UI·테마·내비게이션

ThemeProvider(), useTheme() — src/theme/theme.tsx
  저장한 테마와 시스템 색상 모드에 따라 의미별 색상 토큰을 공급한다.

  셀에 요일·교시·상태 접근성 설명과 눌림 크기 효과를 제공한다.

5. 데이터가 흘러가는 방식
======================================================================

[시간표 수정 예시]
셀 터치 → 해당 팀원 busy만 변경 → AppProvider.update()
→ 화면 즉시 갱신 → persist() → LocalRepository.save() → AsyncStorage.
공강 화면은 같은 최신 Group을 availability()/rankedAvailability()에 전달한다.

[예약 예시]
방·날짜·시간 선택 → 확인 모달 → submit() → update(d => book(d, input))
→ 검증 성공 시 예약 추가·저장, 실패 시 오류 안내.
앱 재실행 시 load() → decodeData() → 전역 상태 복원 → 예약 내역 표시.

데이터는 한 기기의 로컬 상태이다. 서로 다른 팀원의 휴대폰이 동일 모임이나
시간표·예약을 공유하는 구조는 아직 아니다.

현재 로컬 기능의 완성과 전체 서비스의 완성은 구분해야 한다.

[구현되어 있으나 추가 검증이 필요한 부분]
- 실제 Android 실물 기기의 화면·키보드·뒤로 가기·기종별 동작.
- TalkBack, 글자 크기 확대, 시스템 동작 축소의 전체 화면 점검.
- 대량 모임·팀원·예약에서 렌더링·저장 지연과 메모리 사용량.
- 릴리스 빌드의 FPS, 시작 시간, 저사양 실기기 성능.
- 모든 상태 전환에 별도 애니메이션을 세밀하게 적용하는 디자인 고도화.
  현재 애니메이션은 셀 터치·배경 전환·일부 진입/결과/성공 표시 중심이다.
- 자동 UI 시나리오 테스트와 독립 APK 설치 테스트.

[현재 알려진 동작·제약]
- 저장은 AsyncStorage이므로 앱 삭제·데이터 초기화 시 유실될 수 있다.
- 신규 모임은 생성 즉시 저장된다. 나가기 동작이 생성 취소는 아니다.
- 시간표의 반복 요일·교시와 날짜별 예약 시간은 서로 다른 모델이다.
  특정 날짜를 골랐다고 시간표가 자동으로 예약 시간에 매핑되지는 않는다.
- 마지막 요청이었던 시연 기기의 '오픈소스 프로젝트' 삭제·새로고침은
  작업 중지 요청으로 수행하지 않았다. 모임 삭제 기능 자체는 구현되어 있다.

7. 테스트 및 실행 환경 정리
======================================================================

[본 보고서 작성 시 현재 소스로 재확인]
실행 명령: .\Start-KWMeet.ps1 -Task check

자동 테스트 내용:
  01. 30개 블록별 참석·불참 분류와 인원 합계
  02. 참석 인원 내림차순 및 동률의 요일·교시순 정렬
  03. 팀원 추가·삭제 후 인원 계산 및 원본 시간표 보존
  04. 전원 공강·전원 수업 상태 계산
  05. 시드 점유 재현성 및 빈 슬롯/점유 슬롯 존재
  06. 중복 예약 거부, 취소 후 재예약 및 시드 점유 유지
  07. 동일 모임의 같은 시간 다른 방 예약 차단
  08. 방·모임·정원·날짜·시간·과거/범위 초과 입력 검증
  09. 저장 후 새 저장소 인스턴스에서 데이터 복원
  10. 연속 저장 순서와 실패 후 재시도
  11. 손상 데이터 거부 및 원본 보존
  12. 기본 팀원 이름 일회성 갱신과 기존 데이터 보존

저장소 자동 테스트는 MemoryStorage를 사용한다.
실제 AsyncStorage와 Android 화면 전체를 자동 조작하는 E2E 테스트는 아니다.

[앞선 실행 기록 및 사용자 확인]
- Android 16 / API 36 에뮬레이터의 Expo Go 57.0.9에서 앱 실행 확인.
- 사용자가 직접 앱 테스트를 완료하고 정상 동작을 확인함.
  개별 수동 체크리스트 전체 항목을 자동으로 통과 처리한 것은 아님.
- 앞선 Android 개발 번들 생성 성공 기록이 있다.
  이번 문서 작성 과정에서는 에뮬레이터나 앱을 다시 실행하지 않았다.
- 독립 실행 APK 생성·배포와 실물 기기 테스트 완료 기록은 없다.

[오늘 정리한 PC 실행 환경]
- 프로젝트, Android SDK, 가상폰 데이터를 C드라이브로 이전.
- 프로젝트 C:\Android\KWMeetApp / SDK C:\Android\Sdk / AVD C:\Android\AVD.
- 바탕화면 '오픈소스 소프트웨어 프론트엔드 테스트'의 실행 파일 연결 정리.
- RAM 8GB 환경을 고려해 가상폰 RAM 1.5GB·CPU 2개·720p 및
  호스트 GPU·Vulkan 비활성·low RAM 모드, Metro 작업 1개 설정 적용.
- localhost IPv4 우선 설정으로 개발 서버 연결 문제 대응.
- HDD/SSD 전후 속도나 FPS는 측정하지 않았으므로 성능 향상률은 주장하지 않음.

[팀원이 소스를 받아 실행할 때]
frontend 폴더에서 Node.js와 pnpm을 준비한 뒤:
  pnpm install --frozen-lockfile
  pnpm typecheck
  pnpm test
  pnpm check:expo
  pnpm start
Android에서 SDK 57에 맞는 Expo Go로 접속한다.
PC 에뮬레이터 실행은 Android SDK/가상 기기 설정이 필요하다.
현재 PC 전용 실행 경로는 팀원 PC에 맞게 조정해야 한다.
